OAKSCRIPT 0.7.0 - SYNTAX AND BUILT-IN REFERENCE

This describes the implemented Windows x64 runner, not planned features. OakScript's short name is Oak. Source files end in .oak. Names and imported exports are case-sensitive. Square brackets in API signatures mean optional arguments; do not type them. Examples marked BEGIN EXAMPLE / END EXAMPLE are complete source files. Save each example using the indicated filename. Graphics examples that mention assets require those assets beside the example, as described in section 13.

1. RUNNING FILES

From PowerShell, with oakscript.exe in the current directory:

.\oakscript.exe C:/path/to/file.oak
.\oakscript.exe "C:/path with spaces/file.oak" first "second argument"

If the EXE's directory is on PATH:

oakscript C:/path/to/file.oak

Runner options precede the source filename. Arguments following the filename belong to the script, even if they begin with --.

oakscript --help                  oakscript -h
oakscript --version               oakscript -v
oakscript --check program.oak      oakscript check program.oak
oakscript run program.oak
oakscript --bytecode program.oak
oakscript --no-opt program.oak
oakscript --engine bytecode program.oak
oakscript --engine ast program.oak
oakscript --profile program.oak
oakscript --frames 4 game.oak
oakscript --frames 4 --capture frame.png game.oak
oakscript --frames -1 --capture failure.png game.oak
oakscript -- program.oak
oakscript compile program.oak -o program.exe
oakscript compile program.oak --emit-cpp generated.cpp --compiler C:/msys64/mingw64/bin/g++.exe

--check checks the entry file and every reachable import without execution. --bytecode prints compiled bytecode without execution. Bytecode with optimization is the default; ast is the reference interpreter. --profile reports checking/execution times to stderr. --frames closes a graphical program after a positive number of frames. --nowindimlim bypasses Oak's default 16384-pixel window dimension cap. Put it before the source filename. It takes no value and is not passed into Oak args. Native graphics EXEs accept the same flag. Positive 32-bit integer dimensions, GPU capabilities/memory and operating-system limits still apply. --capture requires a .png output; without --frames it captures one frame. --frames -1 requires --capture and removes the frame limit. Only an explicit exit(1) requests capture; returning 1 from __main__, runtime errors and ordinary window close do not. Pending drawing is flushed before saving the first window's entire current canvas, even without render_screen() or a prior presented frame. GPU readback and the full PNG write finish before process exit. No script-side completion loop is needed. Capture preserves current canvas values; it does not execute code after exit(1) to calculate pixels the program has not drawn. Other exits leave an existing output file untouched. No PNG is written if no window was created (for example, a source error before execution). Capture failures are reported separately and preserve the program's exit code. Capture output paths resolve from the terminal's working directory. Console scripts do not initialize graphics. Graphics need a Vulkan GPU driver.

compile checks all imports and emits native Windows x64 machine code via C++ and MinGW-w64 GCC. GCC is required only when compiling. The compiled program needs neither OakScript nor .NET and contains no encoded Oak program, parser or VM. The current backend supports CPU, 2D/3D graphics, audio and GPU compute and rejects unsupported constructs; see docs/NATIVE_COMPILATION.md for its exact API, limitations and resource paths. --emit-cpp writes generated C++ and its support headers for inspection. Native records/schemas/options, collections, generators, closures, recoverable errors, matrices/quaternions and plain .format fields plus %s/%% are supported. Native drawing, fonts, multiple windows, input, shading and compute use hardware OpenGL (4.3 for 3D/shaders/compute); audio uses waveOut. The runner uses Vulkan.

oakscript compile cubesgameti/cubesgameti.oak --libpath . -o cubesgameti.exe
cubesgameti.exe --demo
cubesgameti.exe --oak-frames 3 --oak-capture native-frame.png
cubesgameti.exe --oak-frames -1 --oak-capture native-failure.png

For the foldered Cubes Game entry, keep assets/ beside its native EXE. --compiler PATH or OAKSCRIPT_CXX selects g++; compile --no-opt selects GCC -O0.

Exit codes: 0 success; 1 source/resource/runtime error; 2 CLI usage error; 130 interrupted. exit(code) or an integer __main__ return can supply another code.

2. COMMENTS, STATEMENTS, NAMES AND LITERALS

\# A block comment. It may span lines and contain \# nested comments. #\ #\
\ A line comment runs to the end of the line, including after statements.

Use \# ... #\ for nested block comments. // always means floor division.

Statements end at a newline or semicolon. Indentation is cosmetic. All statement bodies use :( ... ), never braces or indentation alone. Newlines are accepted inside calls, lists, tuples and parameter lists. Commas separate their items, and trailing commas are accepted. There is no general expression line-continuation character.

Identifiers start with a letter or underscore, then letters, digits or _. Numeric literals include decimal, hexadecimal (0xff), binary (0b1010), octal (0o17), digit separators (1_000), scientific notation, and imaginary suffix j. Integers outside signed 64-bit range become bigint literals. true, false and null are literals. null has no general nullable type syntax. Use double-quoted or single-quoted strings:

"hello"    'hello'    "a\nb"    "tab\tvalue"    "\u0041"

Escapes: \n \r \t \\ \" \' and \u followed by four hex digits. Ordinary quoted strings cannot contain a physical newline. Triple double or single quotes accept multiline text. Physical CRLF, CR and LF become \n; escapes work as in ordinary strings, and indentation is preserved.

string text = """first line
second line with "quotes" inside."""

There is no string interpolation or raw-string prefix. Prefer forward slashes in Windows paths, or escape each backslash.

String formatting returns a new string:

"abcd{0}fg{1}".format("e", "h")       "abcdefgh"
"{} {}".format("Oak", 4)              "Oak 4"
"{1}-{0}-{1}".format("a", "b")        "b-a-b"
"{{{0}}}".format("Oak")                "{Oak}"
"123%s56%s" % (4, 7)                  "1234567"
"123%s" % 4                           "1234"
"%s %% %d" % ("Oak", 4)               "Oak % 4"

.format accepts positional arguments, including *value expansion, and returns string. Fields may use nonnegative indices {0}, {1}, etc. or automatic {} fields, but cannot mix the two styles. {{ and }} escape literal braces. Repeated fields and unused .format arguments are permitted. Missing arguments, unmatched braces, named fields and unsupported specifications fail with source-location errors. The bound method is a callable: formatter="{}".format; formatter("Oak"). dir(string_value) returns format and length.

Brace format specifications follow {index:SPEC} or {:SPEC}:

"{:>8}".format("Oak")                 right alignment
"{:_^9}".format("Oak")                underscore fill, center alignment
"{:04d}".format(7)                    "0007"
"{:+06d}".format(7)                   "+00007"
"{:#06x}".format(15)                  "0x000f"
"{:.2f}".format(2.5)                  "2.50"
"{:.1%}".format(0.25)                 "25.0%"
"{0!s:>8}".format(4)                  convert with Oak string formatting

SPEC accepts optional fill+alignment (< left, > right, ^ center, = sign-aware), sign (+, -, space), # alternate form, 0 padding, width, .precision, and type:

s string; d/i decimal integer; x/X hex; o octal; b binary;
f/F fixed float; e/E exponential; g/G general float; % scaled percentage.

Integer brace formats require an integer (bool converts to 0/1), and do not accept precision. A string precision limits its UTF-16 units. Empty fields use Oak's usual string representation: true/false/null retain those spellings. Numeric formats use invariant culture and decimal point; no locale grouping. Width is 0..1,000,000 and precision is 0..1,000; larger requests fail explicitly.

Percent formatting uses a tuple for multiple replacements or any single value for one replacement. A list is one value, not an argument list; wrap a tuple inside a one-item tuple to format it as one value: "%s" % ((1, 2),). Supported conversions: %s, %d/%i/%u, %f/%F, %e/%E, %g/%G, %x/%X, %o, %c. %% is a literal percent and consumes no argument. %s uses Oak string(value); %c accepts one Unicode scalar character or its integer code point. %d/%i/%u truncate float values; %u is a decimal alias and still uses signed integers. Flags -, +, space, # and 0, width and .precision are supported:

"%+05d %.2f" % (7, 2.5)               "+0007 2.50"
"%.4d" % 12                          "0012"
"%-8s" % "Oak"                       left-aligned string

Percent argument counts must match exactly. No mapping-based replacements, dynamic * widths/precisions, nested format fields, !r conversions or f-strings are implemented. This is an Oak formatting API, not all of Python's formatting.

3. VARIABLES, ASSIGNMENTS AND SCOPES

TYPE name = expression           typed declaration
name = expression                inferred declaration, or update
name += value                    also -= *= /= %= //= **= &= |= ^= <<= >>=
object.attribute = value
values[index] = value            list or bytearray element assignment
values[start:stop:step] = items   list or bytearray slice assignment

Declarations require an initial value. An inferred variable keeps the type of its first runtime value. Assignments update the nearest existing binding; if there is no binding they create one in the current scope. int values may initialize float variables. bool converts to int/float in numeric contexts: false becomes 0 and true becomes 1. This applies to arithmetic, comparisons, numeric declarations/assignments, typed arguments/returns, numeric attributes, vector/matrix components and numeric helpers. Conditions, boolean bindings and and/or/not still require bool; numeric/string truthiness is not implicit. Strings do not become numbers and float-to-int narrowing is explicit.

print((x+y)*(z==1))              numeric mask; zero unless z equals 1
int enabled = true              stores 1, not a bool
float disabled = false          stores 0.0

Lists and bytearrays support index/slice assignment. Tuples and strings are immutable. Bytearray elements must be integers from 0 through 255. Blocks, loops and functions create lexical scopes; local declarations do not leak into the parent block. Functions can update existing outer variables. Lists, bytearrays, records and graphics resources share references when assigned. Vectors and matrices copy their components when bound to typed variables. readonly is supported for record/schema fields, not general variables.

Lists, tuples, bytes, bytearrays, ranges and strings support zero-based indexing and negative indexing from the end. Bytes and bytearray indexing return int.

values[0]   values[-1]   values.length   len(values)

Slice forms (start is included, stop is excluded):

values[start:stop]               contiguous selection
values[start:stop:step]          stride; step defaults to 1
values[:]                       shallow copy of the whole collection
values[2:]                      from index 2 to the end
values[:3]                      first three elements
values[::2]                     every second element
values[::-1]                    reversed copy
values[4:0:-2]                  indices 4 and 2

Bounds may be expressions, omitted, or null. Negative bounds count from the end; out-of-range slice bounds clamp rather than failing. A zero step fails. For a negative step, omitted start means the last element and omitted stop means before the first element. An explicit stop of -1 instead means the last element: values[::-1] reverses, while values[:-1:-1] is empty. Slices preserve list/tuple/bytes/bytearray/range/string type. Range slicing is lazy. List copies share their element references, but have independent containers. String slicing, like indexing, operates on UTF-16 code units.

Slice assignment accepts a list, tuple, bytearray, or string of replacements:

values[1:3] = [8, 9, 10]         step 1 may change the collection length
values[::2] = (8, 9)             other steps require an exact count
values[::-1] = values            replacements snapshot before mutation
bytes[1:3] = [0, 255]            validate all bytes before modifying

Owner and bounds evaluate once, from left to right, before the right-hand side. Contiguous insertion with start greater than stop inserts at start. Vectors expose writable .x/.y/.z/.w where the dimension permits them. Colors expose writable .r/.g/.b/.a. There are no multi-component swizzles. Vector components are not accessed with [] and vectors have no .length attribute; use len(vector) for component count, length(vector) for magnitude. String indexing/length uses UTF-16 code units, not grapheme clusters.

5. OPERATORS

In order from lowest to highest binary precedence:

or ||
and &&
== != < > <= >= in not in is is not
|
^
&
<< >>
+ -
* / // %

Exponentiation is right-associative: 2 ** 3 ** 2 means 2 ** (3 ** 2). Unary operators: + - ~ not !. Unary parsing includes exponentiation, so -2 ** 2 means -(2 ** 2). Use parentheses for explicit grouping. Boolean operators require bool and short-circuit. Conditions require bool. Arithmetic uses bool operands as integers; +true and -true return int. / and ** return float for ordinary int operands. Decimal and complex arithmetic retain their types; bigint integer powers stay exact. Integer + - * % remain int when both operands are int or bool. Overflow, division by zero and non-finite results fail. String + concatenates strings; list + and bytearray + create concatenated copies. String % performs percent formatting; numeric % remains arithmetic remainder. Numeric comparisons, ordinal string comparisons and equality are supported. Vector arithmetic operates on components. Vector-left/scalar-right arithmetic is accepted; scalar-left/vector-right supports multiplication. Integer-vector operations must produce integral components within the component range. Matrix multiplication supports same-size matrices and matching float vectors. ^ is XOR, & AND, | OR, ~ complement, << and >> shifts. Integer bitwise values use sign extension; negative shifts fail. // floors division; % retains Oak's truncating remainder convention (-5%3 is -2). bigint arithmetic and nonnegative integer powers retain every bit. Ordinary int ** still returns float; use bigint for exact large powers. Comparison chains evaluate each operand once and stop at the first false comparison. in/not in query membership; is/is not query reference identity (including null). Sets support | & ^ -, and subset ordering. ++ / --, conditional expressions and user-defined operator overloads are absent.

Typed and untyped parameters may be mixed. Arguments may be positional or named. Functions without a receiving rest parameter require an exact expanded count. A final *args collects zero or more remaining arguments in an immutable tuple. Required parameters before it must still be supplied. Only one receiving rest parameter is allowed, and it must be last among positional parameters. Following ordinary parameters are keyword-only. In *TYPE args, TYPE describes each element, not the tuple: elements are checked/coerced before the function body runs. Rest tuples support indexing, slicing, iteration and onward *args expansion. Defaults evaluate once when the declaration executes and retain mutable identity. Required positional parameters precede default parameters. A bare * introduces keyword-only parameters. **kwargs must be last and collects extra string-keyed arguments in a dictionary; **TYPE kwargs checks each value. Duplicate keywords, duplicate positional/named bindings, missing values and unknown keywords fail. Definitions with defaults/decorators execute in source order; ordinary definitions retain Oak's block hoisting. lambda parameters: expression makes a closure. @decorator above def wraps its callable; multiple decorators apply bottom to top.

    int result = first

    return result

Return annotations are optional; declared return types are enforced. Functions are available throughout their containing block, support recursion and capture lexical scopes. They can be assigned/imported as values. Lambdas, generators, yield, exception handling and decorators are implemented. Async/await is not implemented. The maximum nested function-call depth is 256.

Optional entry points:

def __main__():(...)
def __main__(list arguments) -> int:(...)
def __main__(*args) -> int:(...)     CLI strings collected in a tuple
def draw():(...)
def draw(*args):(...)            empty tuple; accepts a zero-argument callback

The runner executes top-level statements, then the entry file's own __main__, then the graphics frame loop if a window exists. __main__ returns int or no value. An imported module's __main__ is not invoked automatically. draw takes no arguments and runs once per frame. An imported draw may be used. Built-in globals: args (list of entry arguments), argc (int), script_path (current module path), pi (float), delta_time (frame seconds, capped at 0.25), and shared render-state objects blend, depth, cull.

7. USER TYPES, SCHEMAS AND OPTIONS

type Name:(TYPE field; TYPE other = DEFAULT)

type Name from SchemaName:(TYPE additional = DEFAULT)

Newlines or semicolons separate fields. Fields are ordered and typed. Types are nominal: separate declarations define distinct types. Schemas supply reusable fields and are also constructible as records. from in a type/schema declaration requires a schema, not class inheritance. Duplicate field names fail. readonly fields reject writes after construction. Constructors accept positional arguments or one tuple. Omitted trailing fields must have defaults. Default expressions run for each instance in the declaration scope; they cannot refer to the instance's fields. Mutable defaults are fresh. An existing instance passed to its own constructor is returned unchanged. Records share references. No methods, generics or record operator overloads.

options Name:(first;second)
options Name:(first, second)
extend options Name:(third)
Name value = <first>

Newlines, commas or semicolons can separate option names. Duplicate values fail. Option sets are nominal, importable and extensible. Extensions apply during static compilation even if their containing block does not execute; the set must be declared/imported before extension. Options require a declared set or an attribute context: untyped value = <first> is not supported. GPU attributes have their own fixed allowed option values (section 12).

Named imports consult aliases in oaklibraries.json, then NAME.oak beside the importing file, CLI/JSON library search paths, and installed packages in the entry project's oak.lock.json. Quoted extensionless paths also gain .oak. Library directories may use main.oak. A SINGLE leading / means importer-relative, not the current drive root. Drive-qualified and UNC paths are absolute. This special leading-/ rule is for imports; it is not a general file-I/O rule. Imports and relative assets do not depend on the terminal's current directory. pkg: explicitly selects installed package resolution; no network request is made by an import. Install dependencies before running the program.

Library configuration: nearest oaklibraries.json, or --libconfig FILE.json:

{"aliases":{"mathlib":"lib/renamed.oak"},"libpath":["shared","C:/OakLibraries"]}

JSON paths resolve beside their JSON file; alias names are case-sensitive.

oakscript --libpath "C:/OakLibraries;D:/Extra" program.oak
oakscript --libpath "C:/One" --libpath "D:/Two" --check program.oak
oakscript compile program.oak --libpath "C:/OakLibraries" -o program.exe

--libpath accepts directories or individual .oak files. CLI paths resolve from the current directory. Valid configured aliases precede local modules; local modules precede CLI paths, then JSON paths and installed packages. Missing libraries prompt in interactive terminals. Enter a quoted or plain .oak path or directory; blank cancels. Selections last for this compilation. --prompt-imports forces asking; --no-prompt-imports disables it. Batch/piped execution and LSP otherwise report the source location and searched paths. exec/evxec imports retain configured search paths. No automatic downloads. See docs/LIBRARY_PATHS.md for full resolution details.

Semicolons separate selected exports, not commas. End a selected import with a physical newline, closing body or end of file. Do not place an unrelated statement after its semicolon on the same physical line. * selects top-level module bindings, including re-exports, but not built-ins, implicit runtime globals, __init__ or __dispose__ hooks. Missing/duplicate/conflicting selections and circular dependencies fail.

Modules have isolated lexical scopes and initialize once, at first executed import. Equivalent normalized paths share the cache. Imported bindings are live: updating an imported variable or calling a library function that changes it is visible to all importers. Imported functions keep the library's scope. Imports in functions/blocks remain in that scope. All reachable imports are checked before execution, including imports in unexecuted branches/functions. An aliased namespace exposes attributes, e.g. lib.value or lib.Point(1, 2). Type aliases such as P work in declarations/annotations. lib.Point p = ... is not an accepted qualified type declaration; import Point as P instead.

Module hooks:

def __init__():(...)
def __dispose__():(...)

Own __init__ runs after a module's top-level statements; imports complete after successful initialization. Own __dispose__ runs once in reverse successful initialization order when the runner exits, including after program errors. Hooks take no arguments. Checks, bytecode dumps and editor analysis never run hooks. Re-exporting a hook does not create a hook in the importing module.

Multiple windows are supported. Width/height must be integers in 1..16384 by default; --nowindimlim bypasses this Oak cap. GPU-supported positive 32-bit dimensions are still required. When Windows limits a window to the monitor size, the full requested canvas is kept on the GPU and fitted into the visible preview without stretching. MATRIX MATH

Matrices store rows and multiply column vectors. A*B*v applies B, then A. GPU projections use +Z forward, +Y up and depth 0..1. All rotation and field of view angles are degrees. Euler vectors mean (pitch X, yaw Y, roll Z), composed as rotation_y(y)*rotation_x(x)*rotation_z(z).

inverse(mat2|mat3|mat4) -> same matrix type
determinant(mat2|mat3|mat4) -> float
matrix_multiply(matrix, matrix, ...) -> same matrix type
perspective(fov_degrees, aspect, near, far) -> mat4
orthographic(left, right, bottom, top, near, far) -> mat4
look_at(eye_vec3, target_vec3, up_vec3) -> mat4

QUATERNIONS

Ordering stays x,y,z,w; identity is quat(0,0,0,1). Quaternion products use Hamilton multiplication: qA*qB*v applies qB first, then qA. Scalar products scale components. q*vec3 rotates a vector using the normalized quaternion.

quat_normalize(quat) -> quat              // normalize(q) also works
quat_inverse(quat) -> quat                // inverse(q) also works
conjugate(quat) -> quat
quat_rotate(quat, vec3) -> vec3            // same as q*v
quat_slerp(first, second, amount) -> quat
quat_nlerp(first, second, amount) -> quat
quat_from_euler(pitch_yaw_roll_vec3) -> quat
quat_to_euler(quat) -> vec3
quat_from_axis_angle(axis_vec3, degrees) -> quat
quat_to_matrix(quat) -> mat4

Interpolation normalizes endpoints and uses the shortest rotational arc; amount must be 0..1. Axis and quaternion normalization require nonzero values. Ordinary stereo preserves independent left/right channels. Mono and spatial voices use equal-power panning. Compute uses the selected window's Vulkan device if the first compute call occurs after window creation. Otherwise it creates a headless Vulkan device. Buffer format is "float" (default), "int" or "uint", all 32-bit. Input lists initialize values; element counts initialize zeros. Buffers have read-only .count int and .format string. Bounds and integer ranges are checked. Maximum buffer allocation is 1 GiB (268435456 elements). Float32 values must be finite. read_buffer returns Oak float for float32, Oak int for int32/uint32.

Image format is "rgba8" (default) or "r32f". Images expose read-only .width, .height ints and .format string. Dimensions are 1..16384, at most 1 GiB of pixels. Rows are top-to-bottom. rgba8 read/write lists contain R,G,B,A integer bytes 0..255 for each pixel. r32f lists contain one float per pixel. Images start at zero. save_image writes a PNG from rgba8 via explicit GPU readback.

dispatch group counts are 1..65535 in each dimension; defaults y/z=1. Local workgroup sizes come from the shader, so 64 invocations per group means a 64-thread local size, not 64 groups. Shader code must bounds-check extra invocations when image/buffer dimensions are not a whole number of groups. Dispatch is asynchronous and queue ordered. read_buffer/read_image/save_image, snapshot_texture and compute_wait wait for their requested results. Explicit image writes order against earlier jobs. Pipelines and descriptor sets cache by shader/binding layout and handles; identical shader paths load once.

Shaders are compiled SPIR-V (.comp.spv), entry "main", with literal local_size_x/y/z. Use GLSL #version 450, one descriptor set (set=0), sequential bindings matching the Oak bindings list. Each buffer is a std430 read/write storage buffer; each image is a formatted read/write storage image. Uniform buffers, samplers, indirect dispatch and runtime GLSL compilation are not part of this API. Write uniforms as small storage buffers when needed.

Light objects are general resources. A window maintains its own active list; adding the same object again is harmless. The same light can be added to multiple windows. Mutating its attributes updates subsequent frames.

.type = <directional> | <point> | <spot>; default <directional>

.outer_angle float degrees 0..<90; default 30
.cast_shadows bool; default false
.shadow_bias float >= 0; default 0.001 (normalized light-depth units)

.shadow_near float > 0; default 0.1 (point/spot shadow projection)
.shadow_filter = <hard> | <pcf>; default <pcf>

For spots, require 0 <= inner_angle <= outer_angle < 90 and outer_angle > 0. The angles are cone HALF-angles. Point/spot range controls attenuation and the shadow far plane; shadow_near must be less than range. Point attenuation is (1-distance/range)**2/(1+distance**2), clipped at range. Spot cones smoothly interpolate between inner and outer cone edges. Direction is where rays travel; directional illumination arrives from its negative. Directional position centers its orthographic shadow volume, extent sets its world width, and range sets coverage along its direction. Configure these for your scene.

3D meshes/models/polygons use diffuse Lambert lighting when the selected window has lights and lighting is enabled. Vertex normals are transformed with the inverse transpose; missing normals fall back to fragment derivatives. 2D graphics, text and existing custom shader programs retain their own appearance. Existing programs with no active lights retain their unlit behavior. roughness/metallic and normal-map textures do not implement PBR.

Shadow casters are submitted 3D mesh/model/polygon geometry with lighting enabled. The GPU renders depth maps before the lit color pass. Directional and spot lights use one map; point lights use six perspective cube faces. The fragment shader projects world positions into those maps and compares depth, with slope-aware receiver bias and receiver-plane PCF correction. <pcf> uses 3x3 taps; <hard> uses one. Alpha below 0.5 in a caster's texture is discarded in its shadow pass. Custom shaders may cast but must supply their own lighting/shadow sampling if they replace the built-in color shader.

Each window supports at most 16 active lights and 32 shadow faces, packed into a 4096x2048 depth atlas (512x512 per face). Exceeding these bounds is an explicit error; no lights or shadows are silently dropped. There are no cascades, dynamic shadow resolution, soft area lights or ray-traced shadows.

FRAME PERFORMANCE

Each Vulkan window uses three frame contexts and fences. A context waits only before reusing its in-flight buffers/command list; there is no WaitForIdle per frame. Resize/capture/cleanup wait for resources they must replace or read; device idle is reserved for final device disposal. Immutable mesh/index arrays, tint results, unchanged transform uniforms, presentation quads, SPIR-V shader objects, pipelines, samplers and surface descriptors are cached. Texture revision changes create a replacement image; older versions are retired after a covering frame fence. Mipmaps generate once per upload rather than every draw. Immediate polygons/text remain dynamic data and upload when rebuilt. Make meshes once for repeated geometry.
